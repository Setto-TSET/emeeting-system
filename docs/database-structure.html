ความสัมพันธ์ของฐานข้อมูล (Target Schema — Prisma/MySQL)

Meeting เป็น entity ศูนย์กลาง ทุกอย่างในการประชุมแตกออกจากตารางนี้ เส้นแสดงความสัมพันธ์ โดยหัวลูกศรชี้ไปฝั่ง N (ฝั่งลูก)

Core entity ตารางลูกของ Meeting Join table (M:N) ตาราง MySQL ที่ migrate แล้วจริง PK 🔑   FK ↗   ∅ = unique

ความสัมพันธ์ชนิดความหมาย

ที่เก็บข้อมูลตามสถานะปัจจุบันของโปรเจค

ตอนนี้ระบบยังเป็น frontend-first — ข้อมูลหลักอยู่ในเบราว์เซอร์ผู้ใช้ (localStorage + IndexedDB) มี MySQL จริงเฉพาะฝั่ง backend transcription/summary

ข้อจำกัดสำคัญ: ข้อมูลใน localStorage/IndexedDB อยู่เฉพาะเครื่องนั้น — เปิดคนละเครื่อง/คนละเบราว์เซอร์จะไม่เห็นข้อมูลเดียวกัน และเปิด DevTools อ่านได้ (ดูแผนแก้ใน docs/superpowers/plans/2026-08-17-realtime-cross-device-sync.md)
