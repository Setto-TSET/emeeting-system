Architecture Overview

สถาปัตยกรรมระบบประชุมออนไลน์

ระบบแยกเป็นสามระนาบที่ไม่ปนกัน — สื่อ วิ่งผ่าน ZegoCloud ตรงระหว่างผู้ใช้, สถานะ ทุกอย่างเก็บที่ backend + MySQL, หน้าเว็บ เสิร์ฟจาก Vercel การแยกแบบนี้ทำให้วิดีโอล่มไม่กระทบผลโหวต และผลโหวตยังตรงกันทุกเครื่องแม้คนเข้าห้องทีหลัง

System

สามระนาบ กับเส้นทางที่ไม่ผ่าน backend

จุดสำคัญของแผนภาพนี้คือเส้นสีที่วิ่งอ้อม backend — วิดีโอและเสียงไม่เคยผ่านเซิร์ฟเวอร์ของเราเลย backend รับผิดชอบเฉพาะ “ความจริงของห้องประชุม” คือใครโหวตอะไร ใครยกมือ เอกสารเปิดหน้าไหน

Frontend

ชั้นของ Next.js — แยก UI ออกจากผู้ให้บริการ

ทุกบริการภายนอกถูกหุ้มด้วย interface ของตัวเองก่อนเสมอ (types.ts คู่กับ implementation) เปลี่ยนผู้ให้บริการวิดีโอหรือ ASR ได้โดยไม่ต้องแตะหน้าจอ

ชั้นที่อยู่หน้าที่
หน้าเว็บ src/app/(app)/ dashboard · meetings · live/[id] · booking · documents · committees · rooms · reports · kiosk · portal และ src/app/join สำหรับผู้เข้าร่วมภายนอก
API route src/app/api/video/token/ ออก ZegoCloud token — เส้นทางเดียวที่ secret ของ Zego ถูกใช้ ไม่หลุดถึง browser
Service seam src/services/ video/ (zego + mock) · signaling/ (WebSocket client) · voting/ · rooms/snapshot · speech/ · transcription/ · summarize/ · fileStorage (IndexedDB)
ตรรกะบริสุทธิ์ src/lib/ authz.ts · access.ts · zegoToken.ts · inviteTokens.ts — เป็น pure function ล้วน ตั้งใจให้ยกไปวางฝั่ง backend ได้ทั้งไฟล์

สิทธิ์สองระดับ

access.ts คุมเมนูและ route แบบหยาบ · authz.ts คุมการกระทำรายชิ้น เช่น ใครเปิดโหวตได้ ใครรับรองรายงานได้

ความลับระดับการประชุม

ลายน้ำตามผู้ใช้ · เบลอเมื่อสลับหน้าต่าง · บล็อกคลิกขวา — ป้องปรามการถ่ายจอ ไม่ใช่การป้องกันเชิงเทคนิค

เอกสาร 4 ระดับการมองเห็น

ไฟล์เก็บใน IndexedDB พร้อม preview PDF/Markdown สิทธิ์ระดับไฟล์ตัดสินที่ canViewFile()

Backend

เซิร์ฟเวอร์เดียว สองโปรโตคอล พอร์ตเดียว

server.ts สร้าง Express app แล้วยัดเข้า http.createServer() ก่อนเรียก attachRealtime() ผูก WebSocket ทับ HTTP server ตัวเดียวกัน — REST กับ WSS จึงใช้พอร์ตและโดเมนเดียวกัน ไม่ต้องตั้ง CORS หรือใบรับรองแยก

ชั้นไฟล์หน้าที่
Entryserver.tsCORS · trust proxy · logging · /health · ผูก realtime
Routesroutes/auth (เข้าได้โดยไม่มี token) · rooms · transcription · summarize · audit
Realtimerealtime/server.ts ตรวจ JWT ตอน handshake · handlers.ts แยกชนิดข้อความ · rooms.ts ทะเบียนห้องใน memory
Repositoriesrepositories/meetings · votes · handRaises · transcript · docShare — SQL อยู่ที่นี่ที่เดียว
Servicesservices/auth (JWT + bcrypt) · claude (สรุปประชุม)
Databasedatabase/connection.ts รองรับทั้ง DATABASE_URL และตัวแปรแยก · schema.sql · migrations.ts · seed.ts

Realtime

เขียนลงฐานข้อมูลก่อน แล้วค่อยกระจาย

ลำดับนี้คือเหตุผลที่คนเข้าห้องทีหลังเห็นผลตรงกับคนที่อยู่มาตั้งแต่ต้น ทุก event ถูกยืนยันลง MySQL ก่อน broadcast ฐานข้อมูลจึงเป็นความจริงชุดเดียว ไม่ใช่ state ที่ค้างอยู่ในแท็บใคร

ชนิดข้อความบน WebSocket

กลุ่มข้อความผลที่เกิด
โหวตvote_create · vote_cast · vote_closeเขียน vote_topics / vote_records แล้วกระจายผลรวม
ยกมือhand_raise · hand_lowerอัปเดต hand_raises พร้อมลำดับคิว
ซับไตเติลsubtitle_textบันทึก transcript_segments ต่อผู้พูด
แชร์เอกสารdoc_share · doc_share_page · doc_share_stopซิงค์เอกสารและเลขหน้าที่ทุกคนกำลังดู

Deployment

ส่วนเส้นทางทดสอบ (Koyeb)เส้นทาง VM (compose)
หน้าเว็บVercel production — เหมือนกันทั้งสองเส้นทาง

ฐานข้อมูลAiven MySQL ภายนอก (Koyeb ไม่มี managed MySQL)MySQL container พร้อม volume
